Fix the PDF text extraction bug in my existing Python RAG project.

### Current status

The BGE-M3 embedding migration is already working successfully.

Current pipeline output:

```text
Extracted: 488 pages, 1,021,449 characters
Cleaned: 481 pages kept
Chunked: 482 chunks
Embedding: BAAI/bge-m3 (local)
Vector size: 1024
Qdrant: 482 vectors stored
```

BGE-M3 and Qdrant are NOT the current problem.

### Actual bug

When I run:

```powershell
python ask.py "What is a noun?"
```

Qdrant retrieves chunks containing corrupted/garbage text such as:

```text
& ? ! & & ? !
! * * ! * ; ! * ;
, , !# A0 & H $0
& & & & G & ; & G
```

instead of actual English grammar text.

As a result, semantic retrieval is poor and Gemini responds:

```text
The document does not cover it.
```

This indicates that the **PDF text extraction/parsing stage is corrupting the PDF's text**, likely because of font encoding/mapping issues.

---

## Goal

Fix the PDF extraction stage so that the actual English text from the PDF is preserved correctly.

The target pipeline must become:

```text
PDF
 ↓
Correct text extraction
 ↓
Real English text
 ↓
Cleaning
 ↓
Chunking
 ↓
BGE-M3
 ↓
1024-dimensional vectors
 ↓
Qdrant
 ↓
Relevant retrieval
 ↓
Gemini
 ↓
Correct answer
```

## Handle font encoding problems

If the PDF uses embedded/custom fonts with broken Unicode mappings, investigate whether the extracted text contains:

* replacement characters
* excessive symbols
* random punctuation
* meaningless character mappings
* extremely low percentage of alphabetic English characters

Add a validation step after extraction.

For example, calculate a rough text-quality score based on:

* alphabetic character ratio
* printable character ratio
* English word ratio
* excessive symbol ratio

Do NOT silently accept pages where extracted text is clearly corrupted.

## Fallback extraction

If the primary PDF extractor produces corrupted text, implement a robust fallback strategy.

Possible approach:

```text
Primary extraction
       ↓
Validate extracted text
       ↓
Is text readable?
   ┌───┴───┐
   YES     NO
    ↓       ↓
 Continue   fallback extraction
```

Try the most reliable available extractor for this PDF.

If the PDF has no usable text layer at all, consider OCR as a fallback.

However, do NOT introduce OCR unnecessarily if the PDF already contains a valid text layer.
